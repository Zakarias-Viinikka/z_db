#Web build instructions for db_wrapper
#1. Build the web files (run from inside db_wrapper/):
   cd db_wrapper
   wasm-pack build --target web --out-dir src/web_output --out-name db_wrapper --no-typescript --no-pack --features web

#2. Copy the entire web_output/ folder into your web project and make it visible to Trunk or whatever is relevant

#3. call worker_wrapper.js to send commands to the database worker and receive responses.

#NOTE: rebuilding the wasm does NOT update worker.js's command list.
# worker.js hand-maps every command name to a LiveForever method. When a
# method is added or changed in macro_core.rs, add it to serializedCommands
# (or noInputCommands) in worker.js by hand, or the worker won't forward it.

#4. the calling side lives in db_helper.rs (this folder). Copy it into your web
#   project's src/ and add `mod db_helper;` to lib.rs. It declares the
#   javascript_im_begging_you extern, the tell_worker_to_do helper, and one
#   pub async fn per command. Each fn hardcodes the command string that
#   worker.js expects and serializes/deserializes payloads via protocol.
#   It needs these deps in your Cargo.toml:
#     js-sys, wasm-bindgen, wasm-bindgen-futures, protocol (path)

#NOTE: worker_wrapper.js has a hardcoded connection name in the initialize
# call at the bottom of the file (default: 'leptos_db'). Each project that
# copies this web_output/ folder should change that string to its own name.
# If two projects use the same name, they share the same OPFS database.
